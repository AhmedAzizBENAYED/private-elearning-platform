DEV NOTE
Two behaviours, never mixed. The reset card carries an “Administrator only” tag, a blue header strip “Reset password” and the sentence “You don’t need the member’s current password”. It is never shown on your own profile. “Set new password” stays disabled until both fields are filled, the two requirements are met and both entries match. It then opens the confirmation dialog: focus starts on Cancel, Esc cancels, Reset password confirms. While the request runs both buttons are locked. On success the dialog closes, the card shows a confirmation, a toast names the member and focus moves to the confirmation. The new password is never displayed again and is not sent by email by this design.
BACKEND GAP — NOT IMPLEMENTED
An endpoint that lets an administrator set another user’s password is not part of the described backend. Designed, not available. Until it exists, hide “Reset password” in the row menu, on the member view and in Account & security. The member list already exists; “Create member” already takes a password.
TO CONFIRM WITH API
Confirm: the endpoint and the permission it needs, the password policy for admin resets (the two requirements shown are a proposal), the exact 403 / 404 / 422 messages, whether the member’s active sessions end, and whether the member must change the password at next sign in. None of this is assumed.
