Motion and interaction

Modern, calm motion for the landing page, in pure CSS and fully optional.

Principles

01

Motion explains

It orients (where am I on the page), confirms (this card is clickable) or reveals (here comes the next section). Nothing moves just to decorate.
02

Rich but calm

Only opacity and transform move (plus one clip-path reveal). Travel stays short, loops are slow (7 to 70 s) and tone-on-tone. Text never moves with the pointer or the scroll.
03

Optional

With “reduce motion” on, every animation, transition, pointer effect and smooth scroll is removed. On touch screens the pointer effects are off. The page reads fully without any of it.

Reduced motion and fallbacks

/* keep this block: it is the whole reduced-motion contract */
@media (prefers-reduced-motion: no-preference) {
  .reveal { animation: rise linear backwards;
            animation-timeline: view();
            animation-range: entry 0% entry 62%; }
  .hero-in { animation: rise .8s var(--ease-out) backwards; }
}
@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
  /* nothing else: elements simply appear in place */
}

/* browsers without scroll-driven animations: no animation,
   content is already visible (progressive enhancement) */
DEV NOTE
Fallbacks: scroll-driven CSS (animation-timeline) runs in current Chromium browsers. Where it is missing, content is simply visible; do not hide elements with JavaScript waiting for an observer. Hover effects use :hover and :focus-visible so keyboard users get the same feedback.
DEV NOTE
Performance: only transform and opacity are animated (no layout properties), one small fixed set of classes, no animation library and no JavaScript. Photos and decorative blocks are aria-hidden; nothing that carries meaning depends on motion.

In the React project

// Framer Motion (React). Same tokens as the CSS; one hook decides everything.
const reduce = useReducedMotion();
const ease = [0.2, 0.7, 0.2, 1];

// 1. headline: words rise out of a mask
<motion.span initial={reduce ? false : { y: "112%" } } animate={ { y: 0 } }
  transition={ { duration: 0.95, ease, delay: 0.35 + i * 0.09 } } />

// 2. cursor-reactive layers (skip on touch and reduce)
const x = useSpring(useTransform(pointerX, [-1, 1], [-depth, depth]),
                    { stiffness: 60, damping: 20 });

// 3. scroll reveal + progress line
const { scrollYProgress } = useScroll();
<motion.div style={ { scaleX: scrollYProgress, originX: 0 } } />
<motion.section initial={ { opacity: 0, y: 28 } }
  whileInView={ { opacity: 1, y: 0 } } viewport={ { once: true, margin: "-10% 0px" } } />

// 4. tilt on hover (desktop only)
<motion.div whileHover={reduce ? undefined : { y: -6, rotateY: 4 } }
            style={ { transformPerspective: 900 } } />
DEV NOTE
Pointer effects in this file: a canvas board has no script, so cursor-reactive layers and the tilt are drawn with CSS hit zones (a 5 × 3 grid over the hero, three strips per card) and the hover selector :has(). In the real app use one pointermove listener (or Framer Motion useMotionValue) and the same depths. Same result, finer tracking.
DEV NOTE
Touch and reduce: no pointer effects on touch screens (hover: none) and none when reduce motion is on. Scroll reveals and the load sequence stay on touch unless reduce motion is set.
