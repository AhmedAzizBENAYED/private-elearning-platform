Data needs & routing

What each screen must be able to read, without assuming any endpoint.

Fields each screen needs — verify against the existing API

Listed as needs, not as endpoints. Field names are left to the developer.
Screen
Data displayed
Login
email, password → access token, user role (ADMIN | MEMBER), display name
Dashboard
display name · courses the member is enrolled in with progress (completed / total video lessons) · last visited lesson (for “Continue”) · published courses not yet enrolled
Catalogue / course card
id, title, short description, thumbnail, module count, video count, enrollment state, progress
Course details
title, description, thumbnail, modules → lessons (id, title, type, duration for videos, state per lesson), progress, enrollment state
Learning · video
lesson title, description, type, duration, video source (from the API), previous / next lesson, completed flag, course progress
Learning · text
lesson title, description, text content (format to confirm)
Learning · document / link
lesson title, description, document access URL from the API / external URL
Admin dashboard
member count, course count, published count, draft count, recently created courses (title, status, modules, lessons, created)
Members
id, full name, email, active flag, created date · create: name, email, password (to confirm)
Courses (admin)
title, status, module count, lesson count, created, last modified, thumbnail
Course editor
course fields, modules (title, position), lessons (title, type, position, file state, duration) · publish / archive
Lesson editor
type, title, description, type-specific fields (video file + duration, document file, text content, URL), position
